# 05 角色权限

## 5.1 组织结构

系统采用四级组织架构，按需启用：

```
集团（Group）         - 顶级法人主体（多公司体系下使用）
   └── 公司（Company）- 法人公司
        └── 区域（Region）- 业务大区，如 华北 / 华东
             └── 门店 / 仓库（Store / Warehouse）- 末端经营单元
```

- 单店客户：仅启用"公司 → 门店"两级
- 连锁客户：启用"公司 → 区域 → 门店"三级
- 集团客户：四级全开

### 组织属性

每个组织节点含：

- 编码、名称、上级、负责人
- 类型（集团 / 公司 / 区域 / 门店 / 仓库）
- 经营范围（省、市、县覆盖）
- 单据前缀（如门店编号 BJ001）
- 启用状态

## 5.2 角色矩阵

系统预置以下角色，可在此基础上自定义：

| 角色 | 主要职责 | 关键权限 |
|------|---------|---------|
| 超级管理员 | 系统初始化、租户管理 | 全部 |
| 集团 / 公司老板 | 经营决策 | 全数据查看，关键审批 |
| 区域经理 | 区域运营 | 本区域全数据，区域内审批 |
| 门店经理 | 单店运营 | 本店全数据，本店审批 |
| 销售员 | 接单、回款 | 自己客户的销售单、报价、应收 |
| 销售主管 | 销售管理 | 部门销售单审批、客户分配 |
| 采购员 | 询价、采购 | 采购模块全部、库存查询 |
| 采购主管 | 采购审批 | 采购模块审批 |
| 仓库管理员 | 出入库执行 | 出入库单创建、盘点、库位 |
| 仓库主管 | 仓储管理 | 仓库模块全部、调拨审批 |
| 服务工程师 | 上门服务 | 自己工单、客户机器、配件查询 |
| 服务调度员 | 派单 | 工单调度、工程师管理 |
| 售后主管 | 三包审核 | 三包索赔区域审核 |
| 财务 | 应收应付、收款付款 | 财务模块全部 |
| 财务主管 | 财务审批 | 大额收付审批、对账确认 |
| 数据管理员 | 主数据维护 | 配件、机型、客户、供应商 CRUD |
| 客服 | 客户接待 | 客户档案、报修接单、查询 |

## 5.3 权限模型

采用 RBAC + 数据权限混合模型：

```
User ──*─ UserRole ──*── Role ──*── Permission
                          │
                          └──*── DataScope
```

### 5.3.1 功能权限（Permission）

四种类型：

| 类型 | 粒度 | 示例 |
|------|------|------|
| MENU | 菜单可见 | 销售管理 / 销售订单 |
| BUTTON | 按钮可点 | 销售订单：新增、审批、删除、导出 |
| FIELD | 字段可见 / 可编辑 | 客户：手机号 / 信用额度 |
| API | 接口可调用 | POST /api/sales-orders |

### 5.3.2 数据权限（DataScope）

控制"看到哪些数据"：

| 范围 | 说明 |
|------|------|
| ALL | 全部数据 |
| ORG | 本组织 + 下级组织 |
| SUB_ORG | 仅下级组织 |
| SELF_ORG | 仅本组织 |
| SELF | 仅本人创建 |
| CUSTOMER_GROUP | 仅指定客户分组 |
| CUSTOM | 自定义条件（jsonb） |

### 5.3.3 字段级权限示例

| 字段 | 销售员 | 财务 | 老板 |
|------|-------|------|------|
| 销售订单：单价 | 可见可编辑 | 只读 | 只读 |
| 销售订单：成本价 | 不可见 | 只读 | 只读 |
| 销售订单：毛利率 | 不可见 | 可见 | 可见 |
| 客户：信用额度 | 只读 | 可编辑 | 可编辑 |
| 客户：身份证 | 不可见 | 只读 | 不可见 |

## 5.4 审批流

可视化流程设计器，按单据类型 + 条件 + 部门配置审批节点。

### 5.4.1 审批触发条件

- 单据类型：销售订单 / 采购订单 / 退货单 / 调拨单 / 盘亏单 / 三包索赔
- 金额阈值：> 10 万走特批
- 折扣阈值：折扣 < 7 折走审批
- 信用余额：超信用额度走特批
- 价格保护：低于成本价走审批
- 其他自定义条件

### 5.4.2 审批节点类型

- 单人审批
- 多人会签（全部通过才通过）
- 多人或签（任一通过即通过）
- 部门主管自动定位
- 上级领导自动定位
- 角色审批（如"财务主管"）

### 5.4.3 审批操作

- 通过 / 驳回 / 转交 / 加签 / 撤回
- 驳回时必填原因
- 审批意见与操作时间留痕
- 审批超时自动催办（钉钉 / 短信）

### 5.4.4 典型审批流示例

**销售订单审批**：

```
DRAFT → 销售员提交 → 销售主管审批 ──┐
                                  │ 金额 > 10 万 ──→ 公司老板审批
                                  └→ 自动通过
                                              ↓
                                       价格 < 7 折 ──→ 销售总监审批
                                       客户超信用 ──→ 财务主管审批
                                              ↓
                                          APPROVED
```

**三包索赔审批**：

```
DRAFT (工程师录入) → 售后主管初审 ─┐
                                  │ 资料完整 ──→ 区域售后中心审核
                                  └ 驳回 ────→ 工程师补充
                                                      │
                                              ┌───────┴───────┐
                                              │ 通过 → 整机厂  │
                                              │ 驳回 → 重审   │
                                              └───────────────┘
```

## 5.5 多租户与多组织隔离

- 数据库级别 `tenant_id` 强制隔离
- 中间件层从登录态注入 tenant_id，所有 SQL 自动追加过滤
- 跨租户数据访问需走管理员 + 显式登录，留审计日志

## 5.6 安全控制

### 5.6.1 身份认证

- 用户名 / 密码 + 强密码策略（长度、复杂度、有效期）
- 二次验证：手机短信 / TOTP（OTP）
- 会话过期：默认 8 小时无操作自动登出
- 登录失败 5 次锁定 15 分钟

### 5.6.2 敏感操作

需二次确认 + 验证码：

- 删除主数据
- 修改信用额度
- 大额收付款
- 用户停用 / 删除
- 角色权限变更

### 5.6.3 操作审计

`audit_log` 记录所有写操作 + 关键查询：

- 用户、动作、资源类型、资源 ID
- 变更前后快照（CREATE / UPDATE / DELETE）
- 来源 IP、User-Agent
- 操作时间

支持按用户 / 单据 / 时间范围检索，热数据保留 6 个月，冷数据归档。

### 5.6.4 数据脱敏

| 字段 | 显示规则 |
|------|---------|
| 客户身份证号 | 中间脱敏 110********1234 |
| 客户银行卡号 | 仅显示后 4 位 |
| 客户手机号 | 中间脱敏 138****5678 |
| 工资 / 提成 | 仅本人 + HR 可见 |

脱敏可按角色解锁查看，解锁查看记入审计。

## 5.7 权限变更最佳实践

- 不直接给个人加权限，而是创建 / 调整角色
- 角色变更需走"权限管理员"审核
- 关键角色（财务主管、超级管理员）至少 2 人，避免单点
- 离职 / 转岗：账号停用流程标准化，权限自动回收
