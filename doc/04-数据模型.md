# 04 数据模型

本章节描述系统核心实体、字段、关系与索引设计。所有实体均含通用审计字段：`id`、`tenant_id`、`org_id`、`created_at`、`created_by`、`updated_at`、`updated_by`、`deleted_at`（软删除）、`version`（乐观锁）。

## 4.3 库存实体

### 4.3.1 inventory 库存余额

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint PK | |
| part_id | bigint FK | 配件 |
| warehouse_id | bigint FK | 仓库 |
| location_id | bigint FK | 库位（可空） |
| batch_no | varchar(64) | 批次号（可空） |
| serial_no | varchar(64) | 序列号（可空） |
| qty_on_hand | decimal(14,4) | 现存量 |
| qty_allocated | decimal(14,4) | 已分配（销售订单锁定） |
| qty_locked | decimal(14,4) | 已锁定（盘点冻结） |
| qty_in_transit | decimal(14,4) | 在途量 |
| avg_cost | decimal(14,6) | 加权平均成本 |
| expire_date | date | 失效日期 |

**索引**：`(tenant_id, part_id, warehouse_id, batch_no, serial_no)` 唯一

**派生量**：

- 可用量 = qty_on_hand − qty_allocated − qty_locked

### 4.3.2 stock_transaction 库存流水

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint PK | |
| part_id | bigint FK | |
| warehouse_id | bigint FK | |
| location_id | bigint FK | |
| batch_no / serial_no | | |
| txn_type | enum | PO_IN / SO_OUT / TRANSFER_IN / TRANSFER_OUT / ADJUST_IN / ADJUST_OUT / RETURN_IN / RETURN_OUT / WARRANTY_RETURN / SCRAP |
| qty | decimal(14,4) | 正负 |
| unit_cost | decimal(14,6) | |
| ref_doc_type | enum | PO / SO / TRANSFER / COUNT / WARRANTY |
| ref_doc_id | bigint | |
| ref_line_id | bigint | |
| txn_at | datetime | |

**关键性质**：

- 流水仅追加，不可修改不可删除
- 回滚通过反向流水记录
- 库存余额 = 该 (part_id, warehouse_id, ...) 所有流水之和（一致性校验脚本）

## 4.8 关键索引与分区策略

| 实体 | 推荐策略 |
|------|---------|
| stock_transaction | 按月分区（按 txn_at），每月独立表，老数据归档 |
| audit_log | 按月分区，热数据保留 6 个月，冷数据归档对象存储 |
| inventory | 按 warehouse_id 分库（多仓规模大时） |
| sales_order / shipping_order | 按 ordered_at 年分区 |
| service_order | 按 created_at 月分区 |

## 4.9 一致性与并发设计

### 4.9.1 库存扣减并发

- 销售订单审核时锁库存：`UPDATE inventory SET qty_allocated = qty_allocated + ? WHERE part_id = ? AND warehouse_id = ? AND qty_on_hand - qty_allocated - qty_locked >= ?`
- 失败回滚 + 提示库存不足
- 出库时再扣减 `qty_on_hand`，同步释放 `qty_allocated`

### 4.9.2 单据状态机

所有单据使用状态机驱动，状态变更必须经过定义好的转换边，禁止跳跃。例如：

```
DRAFT → PENDING → APPROVED → PARTIAL_SHIPPED → SHIPPED → CLOSED
                       ↘ CANCELLED
```

### 4.9.3 财务一致性

- 销售出库 → 应收 → 收款 链路使用最终一致：领域事件驱动，失败重试 + 告警
- 关键节点（成本入账、应收生成）支持幂等键，避免重复处理
