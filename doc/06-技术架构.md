## 6.2 技术选型

### 6.2.1 后端

| 组件 | 选型 | 备注 |
|------|------|------|
| 语言 / 框架 | Java + Spring Boot 3 / Spring Cloud | 稳健、生态成熟 |
| RPC | OpenFeign + HTTP | 简单可观测，必要时引入 gRPC |
| 服务注册 | Nacos | 配置中心 + 注册中心一体 |
| 网关 | Spring Cloud Gateway | 鉴权、限流、灰度 |
| 持久层 | MyBatis-Plus | SQL 灵活、易调优 |
| 数据库 | PostgreSQL 15 | JSONB、分区、CTE 强大 |
| 缓存 | Redis 7 | 会话、热点数据、分布式锁 |
| 消息 | Kafka | 单据流转、异步任务、日志 |
| 全文检索 | Elasticsearch | 配件搜索、客户搜索 |
| OLAP | ClickHouse | 报表与大数据分析 |
| 任务调度 | xxl-job 或 k8s CronJob | 定时任务、补货建议生成 |
| 工作流 | Flowable | 审批流引擎 |
| 对象存储 | MinIO（私有化）/ 阿里云 OSS（云上） | 图片、单据、附件 |

> 备选方案：Go + Gin + Ent 适合小团队 + 高性能场景；Node.js + NestJS 适合需要前后端同语言团队。

## 6.3 服务拆分

按业务边界划分微服务，每个服务独立数据库（最终一致性）：

| 服务 | 主要领域 | 关键数据 |
|------|---------|---------|
| master-data-service | 配件、机型、客户、机器、供应商、字典 | part, machine_model, customer, customer_machine, supplier |
| inventory-service | 库存、出入库、调拨、盘点 | inventory, stock_transaction, transfer_order, stock_count |
| purchase-service | 询价、采购、对账 | purchase_order, receiving_order |
| sales-service | 报价、销售、出库、退货 | sales_order, shipping_order |
| service-service | 工单、保养、调度 | service_order, maintenance_plan |
| warranty-service | 三包索赔、故障件返厂 | warranty_claim |
| finance-service | 应收应付、收付款、成本、补贴 | receivable, payable, payment, subsidy_record |
| analytics-service | 报表、看板、自定义查询 | 读 ClickHouse |
| user-service | 用户、角色、权限、组织 | user, role, permission, organization |
| workflow-service | 审批流引擎 | flowable 表 |
| notification-service | 短信、IM、邮件、推送 | message_log |
| integration-service | 外部系统对接 | 适配器集合 |

### 服务间通信

- 同步：REST + Feign（强一致场景：库存扣减、订单创建）
- 异步：Kafka 事件（最终一致：销售出库 → 应收生成、工单完成 → 三包单创建）
- 防腐层：每个服务对外发布的事件用领域语言，内部 schema 解耦

## 6.4 关键技术决策

### 6.4.1 库存一致性

- **悲观锁 + 行级锁**：销售订单审核扣减预占库存使用 `SELECT ... FOR UPDATE`
- **库存余额表 vs 流水表分离**：余额表用于实时查询，流水表用于追溯与一致性校验
- **每日对账任务**：凌晨跑一致性检查，发现偏差自动告警

### 6.4.2 单据状态机

- 引入轻量状态机框架（Spring StateMachine 或自研）
- 所有单据状态变更必须经过状态机，禁止直接 UPDATE
- 状态变更附加事件，触发下游业务（如订单已审核 → 库存预占）

### 6.4.3 全文检索

- 配件主数据 + 客户档案推送到 Elasticsearch
- 支持中文分词、拼音、缩写、件号模糊搜索
- 双写：DB 落盘后通过 Kafka 异步同步到 ES

### 6.4.4 报表与 OLAP

- 业务库（PostgreSQL）→ Kafka CDC → ClickHouse
- 复杂报表全部走 ClickHouse，业务库不查
- 实时性要求 ≤ 1 分钟

### 6.4.5 弱网 / 离线场景

- 服务工程师 App 本地 SQLite，离线工单创建 + 本地缓存
- 网络恢复后增量同步，冲突按"最后写入获胜 + 提示"处理
- PDA 离线扫码：本地缓存当日任务，扫码动作本地校验，结果同步上送

### 6.4.6 文件存储

- 图片：客户端压缩上传 + 服务端二次压缩，多尺寸缓存
- 单据 PDF：按需生成，缓存 7 天
- 附件保留策略：业务关闭后保留 5 年，归档到冷存储

## 6.6 开放 API

### 6.6.1 OpenAPI 规范

- 全部业务接口符合 OpenAPI 3.1 规范
- 自动生成接口文档（Swagger UI）
- 自动生成 SDK（Java、Python、Node.js）

### 6.6.2 鉴权方式

- 内部前后端：JWT + 短期 token + 刷新 token
- 第三方调用：OAuth 2.0 客户端凭证模式 / API Key + Sign
- 限流：按 API Key 维度限流（默认 100 QPS，可申请提升）

### 6.6.3 主要开放能力

| 类别 | 接口示例 |
|------|---------|
| 主数据 | 配件查询、机型查询、客户机器查询 |
| 业务 | 创建采购单、查询库存、创建销售单、查询订单状态 |
| 售后 | 创建工单、查询工单、上传图片、签字 |
| 财务 | 查询应收、上传支付凭证、对账 |
| 报表 | 销售汇总、库存余额、应收账龄 |

### 6.6.4 Webhook

支持订阅事件，回调到客户端 URL：

- 销售订单状态变更
- 服务工单状态变更
- 三包索赔状态变更
- 物流轨迹更新
- 支付到账

## 6.7 集成接口（外部）

### 6.7.1 整机厂 DMS

- 客户机器档案双向同步（每日批量 + 实时事件）
- 备件订货：本系统 → 整机厂下订
- 三包索赔：本系统 → 整机厂审核
- 政策字典：整机厂 → 本系统拉取（每日）

### 6.7.2 物流系统

- 顺丰、跨越、德邦、中铁等：调用对方 API 下单 + 接收轨迹回写
- 跨区代发：按运费协议自动对账

### 6.7.3 财务

- 凭证导出：金蝶 / 用友 / SAP 标准格式
- 银企直连：收付款明细自动拉取，按规则匹配核销
- 发票：百望 / 航信对接，开票 + 红冲

### 6.7.4 IM / 通知

- 钉钉 / 企微：审批 + 消息推送 + 单点登录
- 短信：阿里云 / 腾讯云
- 邮件：基于 SMTP

### 6.7.5 地图与定位

- 高德 / 百度地图：工单 GPS、上门导航、客户位置
- 服务工程师签到打卡

## 6.8 性能与扩展

### 6.8.1 性能目标

| 场景 | 指标 |
|------|------|
| 列表查询（10 万级数据） | P95 ≤ 500ms |
| 单据创建 | P95 ≤ 1s |
| 配件搜索（全文） | P95 ≤ 200ms |
| 报表（百万级数据） | P95 ≤ 3s |
| 批量导入（1 万行） | ≤ 30s |

### 6.8.2 扩展策略

- 应用层：无状态服务，水平扩展
- 数据库：读写分离，关键表分区，超大客户独立实例
- 缓存：Redis 集群，热点 SKU / 客户加缓存
- 异步化：耗时任务（报表、批量、通知）异步处理

## 6.10 发布流程

- Git 主干：`main` 保护，禁止直接推
- 分支策略：`feature/*` → `develop` → `release/*` → `main`
- 环境：开发 / 测试 / 预发 / 生产
- 发布：CI/CD（GitLab CI / Jenkins），自动化测试 + 自动部署
- 回滚：保留最近 3 版镜像，K8s 一键回滚
- 灰度：网关按租户 / 用户 / 流量比例灰度
